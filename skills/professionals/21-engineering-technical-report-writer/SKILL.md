# Engineering Technical Report Writer

Skill นี้ช่วยแปลงข้อมูลดิบทางวิศวกรรม — ผลการคำนวณ ผลทดสอบ ผลสำรวจ หรือผลการตรวจสอบแบบ — ให้กลายเป็นรายงานทางเทคนิคที่มีโครงสร้างมาตรฐาน อ่านเข้าใจง่ายทั้งสำหรับวิศวกรด้วยกันและผู้บริหาร/ลูกค้าที่ไม่ใช่สายเทคนิค พร้อมระบุสมมติฐาน ข้อจำกัด และข้อเสนอแนะอย่างโปร่งใส

## เมื่อไหร่ควรใช้ skill นี้

- วิศวกรโยธา วิศวกรไฟฟ้า หรือวิศวกรเครื่องกล ต้องสรุปผลการคำนวณโครงสร้าง/ระบบ เป็นรายงานส่งลูกค้าหรือหน่วยงานอนุมัติ
- สถาปนิกหรือนักผังเมือง ต้องทำรายงานประกอบการยื่นขออนุญาตหรือทบทวนแบบ (design review)
- ต้องทำ feasibility study ประเมินความเป็นไปได้ของโครงการก่อนตัดสินใจลงทุน
- นักสำรวจรังวัด ต้องสรุปผลสำรวจภาคสนามเป็นรายงานทางการ
- นักออกแบบผลิตภัณฑ์หรือวิศวกรอุตสาหการ ต้องเขียนรายงานทดสอบต้นแบบ (prototype test report) ก่อนเข้าสู่การผลิตจริง

## ขั้นตอนการทำงาน

### 1. กำหนดขอบเขตและวัตถุประสงค์ของรายงาน
ระบุให้ชัดว่ารายงานนี้ตอบคำถามอะไร (เช่น "โครงสร้างนี้รับน้ำหนักได้ตามมาตรฐานหรือไม่" หรือ "โครงการนี้คุ้มค่าลงทุนหรือไม่") และใครคือผู้อ่านหลัก (วิศวกรผู้ตรวจ, ผู้บริหาร, หน่วยงานราชการ)

### 2. รวบรวมข้อมูลนำเข้าและตรวจสอบความครบถ้วน
รวบรวมข้อมูลดิบทั้งหมด เช่น ผลการคำนวณ ผลทดสอบวัสดุ ผลสำรวจ แบบก่อสร้าง มาตรฐานอ้างอิงที่ใช้ (เช่น มยผ., ASTM, ISO ตามความเหมาะสมของสาขา) หากข้อมูลไม่ครบหรือมีความไม่แน่นอน ให้ระบุไว้อย่างตรงไปตรงมาแทนการสมมติเอง

### 3. ตั้งสมมติฐานและระบุข้อจำกัด (Assumptions & Limitations)
ระบุสมมติฐานที่ใช้ในการคำนวณหรือวิเคราะห์ทุกข้อ (เช่น ค่าน้ำหนักบรรทุกที่ใช้, สภาพดินที่สมมติ, อายุการใช้งานที่ประเมิน) พร้อมข้อจำกัดของการศึกษา เพื่อให้ผู้อ่านเข้าใจขอบเขตความน่าเชื่อถือของผลลัพธ์

### 4. นำเสนอผลการวิเคราะห์/คำนวณอย่างเป็นระบบ
จัดกลุ่มผลลัพธ์ตามหัวข้อทางเทคนิค แสดงสูตร ค่าที่ใช้ และผลลัพธ์อย่างโปร่งใสตรวจสอบย้อนกลับได้ ใช้ตารางและหน่วยวัดที่ถูกต้องสม่ำเสมอ เปรียบเทียบกับเกณฑ์มาตรฐานหรือค่ายอมรับได้ (allowable value) ที่อ้างอิงชัดเจน

### 5. ประเมินความเสี่ยงและทางเลือก (สำหรับ feasibility study หรือ design review)
สรุปทางเลือกที่พิจารณา ข้อดี-ข้อเสียของแต่ละทางเลือกในเชิงเทคนิค ต้นทุน และความเสี่ยง โดยไม่ฟันธงเกินขอบเขตข้อมูลที่มี

### 6. สรุปผลและข้อเสนอแนะ
สรุปว่าผลการศึกษาตอบวัตถุประสงค์ในขั้นตอนที่ 1 อย่างไร ระบุข้อเสนอแนะเชิงปฏิบัติ (เช่น ต้องเสริมโครงสร้างจุดใด หรือควรดำเนินการขั้นตอนต่อไปอย่างไร) และระบุจุดที่ควรให้วิศวกรผู้เชี่ยวชาญเฉพาะทาง/ผู้มีใบอนุญาตตรวจสอบและลงนามรับรองก่อนนำไปใช้จริง

### 7. ตรวจทานความสอดคล้องและจัดรูปแบบขั้นสุดท้าย
ตรวจว่าตัวเลข หน่วย และการอ้างอิงมาตรฐานสอดคล้องกันทั้งฉบับ ไม่มีข้อความที่ขัดแย้งกันเอง และภาคผนวก (การคำนวณละเอียด, ภาพถ่าย, แบบแปลน) แนบครบถ้วนตามที่อ้างอิงในเนื้อหา

## โครงสร้าง Output

```
=== รายงานทางเทคนิค: [ชื่อโครงการ] ===
ผู้จัดทำ: [ชื่อ/ตำแหน่ง]   วันที่: [วันที่]   เลขที่เอกสาร: [ถ้ามี]

1) วัตถุประสงค์และขอบเขต
   [ตอบคำถามอะไร ครอบคลุมอะไรบ้าง]

2) ข้อมูลนำเข้าและมาตรฐานอ้างอิง
   - ข้อมูล: [...]
   - มาตรฐาน/ข้อกำหนดที่ใช้: [...]

3) สมมติฐานและข้อจำกัด
   - [...]

4) ผลการวิเคราะห์/คำนวณ
   [ตาราง: รายการ | ค่าที่คำนวณ | เกณฑ์/ค่ายอมรับได้ | ผ่าน/ไม่ผ่าน]

5) การประเมินทางเลือก (ถ้ามี)
   [ทางเลือก | ข้อดี | ข้อเสีย | ต้นทุน/ความเสี่ยงโดยประมาณ]

6) สรุปผลและข้อเสนอแนะ
   - สรุป: [...]
   - ข้อเสนอแนะ: [...]
   - จุดที่ต้องให้ผู้มีใบอนุญาตตรวจสอบ/ลงนามรับรอง: [...]

7) ภาคผนวก
   [รายการเอกสารแนบ]
```

## ตัวอย่าง

**Input:** วิศวกรโยธาต้องสรุปผลการตรวจสอบกำลังรับน้ำหนักของคานอาคารเก่าก่อนต่อเติมชั้นเพิ่ม โดยมีผลทดสอบกำลังอัดคอนกรีตและแบบเดิมประกอบ

**Output (คร่าวๆ):**
- วัตถุประสงค์: ประเมินว่าคานชุดเดิมรับน้ำหนักเพิ่มจากการต่อเติมชั้น 3 ได้หรือไม่
- สมมติฐาน: ใช้ค่ากำลังอัดคอนกรีตจากผลทดสอบ core sample ล่าสุด เนื่องจากไม่มีเอกสาร mix design ต้นฉบับ
- ผลการวิเคราะห์: โมเมนต์ดัดที่เกิดขึ้นจริงเทียบกับกำลังรับโมเมนต์ของคาน → "คาน B1-B4 มีกำลังรับน้ำหนักเพียงพอ ส่วนคาน B5 มีค่าใกล้เคียงขีดจำกัด ควรเสริมกำลัง"
- ข้อเสนอแนะ: เสริมโครงสร้างคาน B5 ก่อนดำเนินการต่อเติม และให้วิศวกรโครงสร้างที่มีใบอนุญาตตรวจสอบแบบเสริมกำลังก่อนก่อสร้างจริง

## เกณฑ์คุณภาพ

- [ ] ระบุวัตถุประสงค์และขอบเขตของรายงานชัดเจนตั้งแต่ต้น
- [ ] แสดงสมมติฐาน ข้อมูลนำเข้า และมาตรฐานอ้างอิงอย่างโปร่งใส ตรวจสอบย้อนกลับได้
- [ ] ไม่ระบุค่ามาตรฐาน ตัวเลขเกณฑ์ หรือรหัสมาตรฐานที่ไม่แน่ใจ — ให้ระบุว่าต้องตรวจสอบกับมาตรฐาน/แหล่งอ้างอิงที่เกี่ยวข้องแทนการเดา
- [ ] แยกส่วนข้อเท็จจริง (ผลคำนวณ/ทดสอบ) ออกจากส่วนความเห็นและข้อเสนอแนะอย่างชัดเจน
- [ ] ระบุอย่างชัดเจนว่าจุดใดต้องให้วิศวกร/ผู้เชี่ยวชาญที่มีใบอนุญาตตรวจสอบและลงนามรับรองก่อนนำไปใช้จริง
- [ ] ภาษาที่ใช้อ่านเข้าใจได้ทั้งผู้เชี่ยวชาญและผู้มีส่วนได้ส่วนเสียที่ไม่ใช่สายเทคนิค
