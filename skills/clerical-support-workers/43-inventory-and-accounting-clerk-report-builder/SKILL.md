# Inventory and Accounting Clerk Report Builder

Skill นี้ช่วยเสมียนบันทึกตัวเลขและวัสดุ จัดทำรายงานกระทบยอดสินค้าคงคลัง สรุปบัญชีเบื้องต้น และสรุปข้อมูลเงินเดือน จาก "ตัวเลขที่ผู้ใช้ให้มาจริงเท่านั้น" หน้าที่หลักคือจัดระเบียบ ตรวจสอบความสอดคล้อง และนำเสนอให้อ่านง่าย ไม่ใช่การคำนวณภาษีหรือปิดงบบัญชีที่ต้องอาศัยดุลพินิจทางวิชาชีพบัญชี

## เมื่อไหร่ควรใช้ skill นี้

- พนักงานคลังสินค้า/สต๊อกต้องการกระทบยอดสินค้าคงคลังระหว่างยอดในระบบกับยอดนับจริง
- เสมียนบัญชีต้องการสรุปรายการรับ-จ่ายประจำเดือนให้เป็นตารางอ่านง่ายก่อนส่งฝ่ายบัญชีตรวจ
- พนักงานเงินเดือนต้องการสรุปยอดเงินเดือนสุทธิของพนักงานแต่ละคนจากข้อมูลชั่วโมงทำงาน/อัตราจ้างที่มีอยู่แล้ว
- พนักงานสถิติหรือพนักงานวางแผนการผลิตต้องการจัดรูปตัวเลขการผลิต/สต๊อกให้เป็นรายงานสรุป
- พนักงานธุรการขนส่งต้องการสรุปรายการเดินรถหรือปริมาณสินค้าที่จัดส่งเป็นรายงานประจำงวด

## ขั้นตอนการทำงาน

### 1. รับข้อมูลตั้งต้นและยืนยันแหล่งที่มา
รวบรวมตัวเลขทั้งหมดที่ผู้ใช้ให้มา (ยอดในระบบ, ยอดนับจริง, รายการรับ-จ่าย, ชั่วโมงทำงาน ฯลฯ) และระบุแหล่งที่มาของแต่ละชุดตัวเลขให้ชัดเจน เพื่อให้ตรวจสอบย้อนกลับได้

### 2. ตรวจสอบความครบถ้วนของข้อมูล
- เช็คว่ามีตัวเลขครบทุกรายการที่จำเป็นสำหรับรายงานประเภทนั้นหรือไม่
- ถ้าข้อมูลบางส่วนขาด ให้ระบุชัดเจนว่าขาดอะไร แทนการประมาณการหรือเดาแทน

### 3. จัดทำรายงานกระทบยอดสินค้าคงคลัง (ถ้าเกี่ยวข้อง)
- เทียบยอดคงเหลือตามระบบ (book stock) กับยอดที่นับได้จริง (physical count) ทีละรายการ
- คำนวณผลต่าง (variance) = ยอดนับจริง − ยอดในระบบ
- จัดกลุ่มผลต่างเป็น: ตรงกัน / ขาด (shortage) / เกิน (overage) พร้อมช่องให้ระบุสาเหตุที่พบ (เช่น สินค้าเสียหาย, บันทึกผิด, ยังไม่ตัดสต๊อก)

### 4. จัดทำสรุปบันทึกบัญชี/เงินเดือนเบื้องต้น (ถ้าเกี่ยวข้อง)
- จัดกลุ่มรายการรับ-จ่ายตามหมวดหมู่ที่ผู้ใช้กำหนด (เช่น รายรับ, ค่าใช้จ่ายดำเนินงาน, เงินเดือน)
- สำหรับเงินเดือน: สรุปยอดตามสูตรที่ผู้ใช้ให้มาเท่านั้น เช่น เงินเดือนสุทธิ = เงินเดือนฐาน + ค่าล่วงเวลา − รายการหัก (ใช้ตัวเลขและสูตรที่ผู้ใช้ระบุ ไม่ใช้อัตราภาษี/ประกันสังคมที่ไม่ได้รับมา)
- รวมยอดแต่ละหมวดและยอดรวมทั้งหมด พร้อมแสดงวิธีคำนวณอย่างโปร่งใส

### 5. ตรวจทานความสมเหตุสมผลของตัวเลข
- เช็คว่ายอดรวมย่อยบวกกันแล้วตรงกับยอดรวมใหญ่หรือไม่
- สังเกตตัวเลขที่ผิดปกติชัดเจน (เช่น ติดลบในช่องที่ไม่ควรติดลบ) แล้วแจ้งผู้ใช้ให้ตรวจสอบ แทนการแก้เอง

### 6. จัดรูปแบบรายงานให้อ่านง่าย
- ใช้ตารางแยกหมวดหมู่ชัดเจน เรียงลำดับตามความสำคัญหรือช่วงเวลา
- ใส่ยอดรวมท้ายตารางและวันที่จัดทำรายงาน

### 7. สรุปประเด็นที่ต้องส่งต่อให้ผู้มีอำนาจตรวจสอบ
- ระบุรายการที่มีผลต่างผิดปกติหรือข้อมูลไม่ครบ ให้ส่งต่อฝ่ายบัญชี/หัวหน้างานตรวจสอบก่อนใช้เป็นทางการ

## โครงสร้าง Output

```
=== รายงาน [กระทบยอดสต๊อก / สรุปบัญชี / สรุปเงินเดือน] ===
งวด/วันที่: [ระบุ]
แหล่งข้อมูล: [ระบุที่มาของตัวเลข]

ตารางสรุป:
| รายการ | ยอดตามระบบ/ที่ให้มา | ยอดนับจริง/ยอดจริง | ผลต่าง | หมายเหตุ |
|---|---|---|---|---|
| [รายการ 1] | [ค่า] | [ค่า] | [ค่า] | [สาเหตุถ้ามี] |

ยอดรวมทั้งหมด: [ค่า]

ประเด็นที่ต้องตรวจสอบเพิ่มเติม:
- [รายการที่ผิดปกติหรือข้อมูลไม่ครบ]
```

## ตัวอย่าง

**Input:** "ช่วยกระทบยอดสต๊อก สินค้า A ยอดในระบบ 500 ชิ้น นับจริงได้ 480 ชิ้น, สินค้า B ยอดในระบบ 200 ชิ้น นับจริงได้ 205 ชิ้น"

**Output (คร่าวๆ):**
```
| รายการ | ยอดตามระบบ | ยอดนับจริง | ผลต่าง | หมายเหตุ |
|---|---|---|---|---|
| สินค้า A | 500 | 480 | -20 (ขาด) | ต้องตรวจสอบสาเหตุ |
| สินค้า B | 200 | 205 | +5 (เกิน) | ต้องตรวจสอบสาเหตุ |

ประเด็นที่ต้องตรวจสอบเพิ่มเติม:
- สินค้า A ขาด 20 ชิ้น และสินค้า B เกิน 5 ชิ้น ควรตรวจสอบกับผู้รับผิดชอบคลังก่อนปิดยอด
```

## เกณฑ์คุณภาพ

- [ ] ใช้ตัวเลขที่ผู้ใช้ให้มาเท่านั้น ไม่แต่งหรือประมาณยอดบัญชี ภาษี หรือยอดคงคลังที่ไม่ได้รับมา
- [ ] แสดงวิธีคำนวณผลต่าง/ยอดรวมอย่างโปร่งใส ตรวจสอบย้อนกลับได้ทุกตัวเลข
- [ ] จัดกลุ่มรายการชัดเจนตามประเภทรายงาน (สต๊อก/บัญชี/เงินเดือน)
- [ ] ระบุรายการที่ข้อมูลขาดหรือมีผลต่างผิดปกติแยกไว้ให้ตรวจสอบเพิ่ม แทนการปิดยอดเองทันที
- [ ] ยอดรวมย่อยและยอดรวมใหญ่สอดคล้องกัน ไม่มีการคำนวณผิดพลาด
- [ ] รูปแบบตารางอ่านง่าย มีวันที่และแหล่งที่มาของข้อมูลกำกับชัดเจน
