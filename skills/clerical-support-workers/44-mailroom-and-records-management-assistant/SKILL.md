# Mailroom and Records Management Assistant

Skill นี้ช่วยเสมียนสนับสนุนงานสำนักงานทั่วไป ออกแบบระบบจัดเก็บเอกสารที่ค้นหาเจอง่าย ลดเอกสารหาย และวางระบบบันทึกการรับ-ส่งไปรษณีย์/พัสดุที่ติดตามสถานะได้ชัดเจน เหมาะกับงานที่ต้องจัดการเอกสารหรือสิ่งของจำนวนมากให้เป็นระบบและตรวจสอบย้อนหลังได้

## เมื่อไหร่ควรใช้ skill นี้

- เสมียนแฟ้มเอกสารต้องการออกแบบระบบจัดเก็บแฟ้มให้เป็นหมวดหมู่ชัดเจนและค้นหาได้เร็ว
- พนักงานไปรษณีย์ในองค์กรต้องการระบบบันทึกการรับ-ส่งจดหมาย/พัสดุที่ติดตามได้ว่าส่งถึงใครแล้วหรือยัง
- เสมียนงานบุคคลต้องจัดระบบแฟ้มประวัติพนักงานให้เป็นมาตรฐานเดียวกันทุกคน
- เสมียนห้องสมุดต้องการระบบจัดหมวดหมู่และติดตามการยืม-คืนเอกสาร/สื่อสิ่งพิมพ์
- พนักงานเข้ารหัส/พิสูจน์อักษรต้องการโครงสร้างจัดเก็บไฟล์งานที่ผ่านการตรวจแล้วให้เป็นระเบียบ

## ขั้นตอนการทำงาน

### 1. สำรวจปริมาณและประเภทเอกสาร/สิ่งของ
สอบถามหรือประเมินจากข้อมูลที่มี: ประเภทเอกสาร (สัญญา/ใบเสร็จ/ประวัติพนักงาน/จดหมาย/พัสดุ), ปริมาณโดยประมาณต่อเดือน, และผู้ใช้งานระบบ (คนเดียวหรือหลายแผนก)

### 2. ออกแบบโครงสร้างหมวดหมู่ (taxonomy)
- กำหนดหมวดหลัก-หมวดย่อยที่ไม่ทับซ้อนกัน เช่น ตามแผนก → ตามประเภทเอกสาร → ตามปี
- ตั้งชื่อรหัสแฟ้ม/โฟลเดอร์ให้สั้น สื่อความหมาย และเรียงลำดับได้ตามตัวอักษรหรือตัวเลข (เช่น HR-2569-สัญญาจ้าง)

### 3. กำหนดกฎการตั้งชื่อไฟล์และแฟ้ม
- รูปแบบมาตรฐานเดียวกันทั้งระบบ เช่น [รหัสหมวด]_[ชื่อเรื่องย่อ]_[วันที่ YYYYMMDD]
- ระบุกฎการเก็บเวอร์ชัน (ถ้ามีการแก้ไขเอกสารซ้ำ) และระยะเวลาการเก็บรักษา/ทำลายเอกสารแต่ละประเภท

### 4. ออกแบบสมุด/แบบฟอร์มบันทึกรับ-ส่งไปรษณีย์
- ฟิลด์ที่ต้องมี: วันที่รับ/ส่ง, ประเภท (จดหมาย/พัสดุ/เอกสารด่วน), ผู้ส่ง, ผู้รับปลายทางภายในองค์กร, หมายเลขติดตาม (ถ้ามี), สถานะ (รอส่งมอบ/ส่งมอบแล้ว), ผู้เซ็นรับ

### 5. วางขั้นตอนการรับ-ส่งจริง
- ระบุลำดับ: รับเข้า → บันทึกลงทะเบียน → คัดแยกตามผู้รับ/แผนก → นำส่ง → ให้ผู้รับเซ็นยืนยัน → ปิดสถานะในระบบ
- กำหนดวิธีติดตามรายการที่ค้างส่งมอบเกินระยะเวลาที่กำหนด

### 6. สร้างแนวทางค้นหาและเรียกคืนเอกสาร
- อธิบายวิธีค้นหาเอกสารจากระบบหมวดหมู่ที่ออกแบบไว้ ทั้งกรณีรู้ชื่อไฟล์และไม่รู้ชื่อไฟล์ (ค้นจากหมวด/วันที่/ผู้เกี่ยวข้อง)
- กำหนดผู้มีสิทธิ์เข้าถึงเอกสารแต่ละประเภท โดยเฉพาะเอกสารที่มีข้อมูลส่วนบุคคล เช่น แฟ้มประวัติพนักงาน

### 7. จัดทำแนวทางเก็บรักษา/ทำลายเอกสาร
- ระบุระยะเวลาจัดเก็บของแต่ละประเภทเอกสาร (ให้ผู้ใช้ยืนยันตามระเบียบองค์กร/กฎหมายที่เกี่ยวข้อง แทนการกำหนดเองโดยไม่มีข้อมูลอ้างอิง)

## โครงสร้าง Output

```
=== ระบบจัดเก็บเอกสาร: [ชื่อหน่วยงาน/แผนก] ===

โครงสร้างหมวดหมู่:
[หมวดหลัก]
  └─ [หมวดย่อย 1]
  └─ [หมวดย่อย 2]

กฎการตั้งชื่อไฟล์: [รูปแบบ]
ระยะเวลาจัดเก็บ: [ประเภทเอกสาร] → [ระยะเวลา] (ต้องยืนยันตามระเบียบองค์กร)

=== สมุดบันทึกรับ-ส่งไปรษณีย์/พัสดุ ===
| วันที่ | ประเภท | ผู้ส่ง | ผู้รับ | หมายเลขติดตาม | สถานะ | ผู้เซ็นรับ |
|---|---|---|---|---|---|---|
| [วันที่] | [จดหมาย/พัสดุ] | [ชื่อ] | [ชื่อ/แผนก] | [เลข] | [รอส่ง/ส่งแล้ว] | [ชื่อ] |
```

## ตัวอย่าง

**Input:** "ช่วยออกแบบระบบแฟ้มเอกสารฝ่ายบุคคล บริษัทมีพนักงาน 50 คน มีทั้งสัญญาจ้าง ใบลา และประวัติการอบรม"

**Output (คร่าวๆ):**
```
HR
 └─ 01-สัญญาจ้าง
      └─ [ชื่อพนักงาน]_สัญญาจ้าง_[วันที่เริ่มงาน]
 └─ 02-ใบลา
      └─ [ปี]_[ชื่อพนักงาน]_ใบลา
 └─ 03-ประวัติการอบรม
      └─ [ชื่อพนักงาน]_อบรม_[ชื่อหลักสูตร]_[ปี]

กฎการตั้งชื่อ: [รหัสหมวด]_[ชื่อพนักงาน]_[รายละเอียด]_[วันที่]
สิทธิ์การเข้าถึง: เฉพาะฝ่ายบุคคลและผู้บังคับบัญชาตรงของพนักงานคนนั้น
```

## เกณฑ์คุณภาพ

- [ ] โครงสร้างหมวดหมู่ไม่ทับซ้อนกัน และค้นหาเอกสารได้จากหลายมุม (ชื่อ/วันที่/ประเภท)
- [ ] กฎการตั้งชื่อไฟล์สม่ำเสมอ ใช้ได้กับเอกสารทุกประเภทในระบบ
- [ ] สมุดบันทึกรับ-ส่งมีฟิลด์ครบสำหรับติดตามสถานะจนถึงส่งมอบสำเร็จ
- [ ] ระบุสิทธิ์การเข้าถึงเอกสารที่มีข้อมูลส่วนบุคคลอย่างชัดเจน
- [ ] ไม่กำหนดระยะเวลาจัดเก็บ/ทำลายเอกสารตามกฎหมายขึ้นเองโดยไม่มีข้อมูลอ้างอิง ต้องให้ผู้ใช้ยืนยันตามระเบียบจริง
- [ ] ระบบเสนอสามารถปรับขนาดได้ตามปริมาณเอกสารที่เพิ่มขึ้นในอนาคต
