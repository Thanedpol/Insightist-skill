# Budget Variance Report

Skill นี้ช่วยเปรียบเทียบตัวเลขที่ "วางแผนไว้ (budget)" กับ "สิ่งที่เกิดขึ้นจริง (actual)" ในแต่ละหมวดค่าใช้จ่ายหรือรายได้ หา variance ที่ผิดปกติ วิเคราะห์ว่าน่าจะเกิดจากอะไร แล้วสรุปเป็นข้อเสนอแนะให้ผู้บริหารนำไปตัดสินใจต่อได้ทันที เหมาะสำหรับทีมการเงิน เจ้าของธุรกิจ หรือหัวหน้าแผนกที่ต้องรายงานผลงบประมาณประจำเดือน/ไตรมาส/ปี

## เมื่อไหร่ควรใช้ skill นี้

- มีไฟล์หรือข้อมูลที่มีทั้งคอลัมน์ "งบประมาณ" และ "ยอดจริง" แล้วต้องการรู้ว่าต่างกันตรงไหน
- ต้องการรู้ว่าแผนก/โครงการไหนใช้งบเกินหรือต่ำกว่าแผนอย่างมีนัยสำคัญ
- ปิดงบประจำเดือน/ไตรมาส และต้องเตรียมรายงานสรุปให้ผู้บริหารหรือบอร์ด
- ต้องการหาสาเหตุว่าทำไมค่าใช้จ่ายจริงถึงสูง/ต่ำกว่าที่ตั้งไว้ ก่อนวางแผนงบงวดถัดไป
- ต้องการ flag รายการที่เบี่ยงเบนผิดปกติ (เช่น เกิน 10-15% ของงบ) ให้ผู้บริหารสนใจก่อน
- เปรียบเทียบผลงบประมาณระหว่างหลายแผนก หลายโครงการ หรือหลายสาขา

## ขั้นตอนการทำงาน

### 1. เตรียมและจัดโครงสร้างข้อมูล
- รวบรวมข้อมูลเป็นตารางที่มีอย่างน้อย: หมวดรายการ (line item), งบประมาณ (budget), ยอดจริง (actual)
- ถ้ามีหลายแผนก/หลายเดือน ให้จัดกลุ่มตามมิติที่ต้องการวิเคราะห์ (เช่น แยกตามแผนก แล้วแยกตามหมวดค่าใช้จ่ายในแต่ละแผนก)
- ตรวจสอบว่าหน่วยเงินและช่วงเวลาตรงกัน (เช่น budget รายปีอย่าไปเทียบกับ actual สะสมแค่ 3 เดือนโดยไม่ปรับสัดส่วน)

### 2. คำนวณ Variance
สำหรับทุกหมวดรายการ:
- **Variance (บาท)** = ยอดจริง (Actual) − งบประมาณ (Budget)
- **Variance (%)** = [(ยอดจริง − งบประมาณ) ÷ งบประมาณ] × 100
- สำหรับ "ค่าใช้จ่าย": Variance เป็นบวก = ใช้เกินงบ (Unfavorable), เป็นลบ = ใช้ต่ำกว่างบ (Favorable)
- สำหรับ "รายได้": Variance เป็นบวก = ทำได้ดีกว่าแผน (Favorable), เป็นลบ = ทำได้แย่กว่าแผน (Unfavorable)
- ระบุสถานะ Favorable (F) / Unfavorable (U) กำกับทุกแถวให้ชัดเจน อย่าใช้แค่เครื่องหมายบวกลบเฉยๆ เพราะความหมาย F/U กลับกันระหว่างรายได้กับค่าใช้จ่าย

### 3. กำหนดเกณฑ์ความสำคัญ (Materiality Threshold)
- ตั้งเกณฑ์ว่า variance ระดับไหนถือว่า "ต้องสนใจ" เช่น เกิน ±10% หรือเกิน ±5% ของยอดงบรวม (จำนวนเงินขั้นต่ำ) แล้วแต่ขนาดธุรกิจ — ถ้าผู้ใช้ไม่ระบุ ให้ใช้ ±10% เป็นค่าเริ่มต้นและระบุไว้ในรายงานว่าใช้เกณฑ์นี้
- แยกรายการที่เกินเกณฑ์ออกมาเป็น "รายการที่ต้องวิเคราะห์สาเหตุเชิงลึก" ส่วนรายการที่ variance เล็กน้อยให้สรุปรวมได้โดยไม่ต้องลงรายละเอียด

### 4. วิเคราะห์สาเหตุของ variance ที่มีนัยสำคัญ
สำหรับแต่ละรายการที่เกินเกณฑ์ ให้พิจารณาสาเหตุที่เป็นไปได้ตามหมวดหมู่ทั่วไป:
- **Price/Rate variance**: ราคาต้นทุนต่อหน่วยเปลี่ยน (เช่น ราคาวัตถุดิบขึ้น ค่าแรงขึ้น)
- **Volume/Quantity variance**: ปริมาณการใช้จริงต่างจากแผน (เช่น ขายได้มากกว่าคาด เลยต้นทุนวัตถุดิบสูงตาม)
- **Timing variance**: รายการที่ตั้งงบไว้เดือนอื่น แต่จ่ายจริงเดือนนี้ (ไม่ใช่ variance จริง แค่ timing เหลื่อม)
- **One-time/Non-recurring items**: ค่าใช้จ่ายที่ไม่ได้เกิดประจำ (เช่น ค่าปรับ ค่าซ่อมฉุกเฉิน)
- **Planning error**: ตั้งงบประมาณผิดพลาดตั้งแต่แรก ประเมินต่ำ/สูงเกินจริง
- ถ้าข้อมูลที่มีไม่พอฟันธงสาเหตุ ให้เสนอเป็น "สมมติฐานที่เป็นไปได้" พร้อมแนะนำว่าควรถามใครหรือดูข้อมูลอะไรเพิ่มเพื่อยืนยัน

### 5. จัดลำดับความสำคัญของรายการที่ควรจับตา
- เรียงรายการที่ variance มีนัยสำคัญจากผลกระทบมากไปน้อย (ตามจำนวนเงินสัมบูรณ์ ไม่ใช่แค่ %) เพราะรายการเล็กที่ % สูงอาจไม่กระทบเท่ารายการใหญ่ที่ % ต่ำ
- ระบุว่ารายการไหนเป็นความเสี่ยงต่อเนื่อง (จะเกิดซ้ำทุกเดือน) กับรายการไหนเป็นเหตุการณ์ครั้งเดียว

### 6. สรุปข้อเสนอแนะเชิงบริหาร (Actionable Recommendations)
สำหรับแต่ละประเด็นสำคัญ ให้เสนอแนะเป็นข้อปฏิบัติที่ชัดเจน เช่น:
- ปรับงบประมาณงวดถัดไปให้สอดคล้องกับแนวโน้มจริง
- ขออนุมัติเพิ่มเติมถ้าค่าใช้จ่ายที่เกินเป็นสิ่งจำเป็นต่อธุรกิจ
- ตั้งมาตรการควบคุมต้นทุนในหมวดที่เกินงบต่อเนื่อง
- ทบทวนสมมติฐานการตั้งงบประมาณที่ผิดพลาดซ้ำๆ

## ตัวอย่าง

**Input:** แผนกการตลาด เดือนสิงหาคม 2568 — งบโฆษณาออนไลน์ 200,000 บาท ใช้จริง 265,000 บาท / งบจัดอีเวนต์ 150,000 บาท ใช้จริง 140,000 บาท / งบเงินเดือนทีม 300,000 บาท ใช้จริง 300,000 บาท

**Output (คร่าวๆ):**
- โฆษณาออนไลน์: Variance = 265,000 − 200,000 = +65,000 บาท (+32.5%) → **Unfavorable** เกินเกณฑ์นัยสำคัญ (±10%) ชัดเจน สาเหตุที่เป็นไปได้: ค่า CPC แพลตฟอร์มโฆษณาปรับขึ้นช่วงเทศกาล หรือทีมเพิ่มงบยิงแอดเองโดยไม่แจ้ง ควรตรวจสอบใบแจ้งหนี้แพลตฟอร์มโฆษณาย้อนหลังเพื่อยืนยันสาเหตุ
- จัดอีเวนต์: Variance = 140,000 − 150,000 = −10,000 บาท (−6.7%) → Favorable แต่ไม่เกินเกณฑ์นัยสำคัญ ไม่ต้องลงรายละเอียดเพิ่ม
- เงินเดือนทีม: Variance = 0 บาท (0%) → ตรงตามแผนพอดี
- **ข้อเสนอแนะ:** ทบทวนงบโฆษณาออนไลน์ของเดือนถัดไปให้สอดคล้องกับต้นทุนจริง และตั้งเพดานอนุมัติล่วงหน้าหากมีการเพิ่มงบยิงแอดเกิน 10% ของแผน

## เกณฑ์คุณภาพ

- [ ] คำนวณ variance ทั้งจำนวนเงินและเปอร์เซ็นต์ให้ครบทุกรายการ พร้อมระบุ Favorable/Unfavorable อย่างถูกต้องตามประเภทรายการ (รายได้ vs ค่าใช้จ่าย)
- [ ] ระบุเกณฑ์นัยสำคัญ (threshold) ที่ใช้อย่างชัดเจน และแยกรายการที่ต้องวิเคราะห์เชิงลึกออกจากรายการปกติ
- [ ] วิเคราะห์สาเหตุของ variance สำคัญโดยอ้างอิงหมวดหมู่สาเหตุที่สมเหตุสมผล ไม่ใช่เดาแบบไม่มีหลัก
- [ ] จัดลำดับความสำคัญตามผลกระทบจริง (จำนวนเงิน) ไม่ใช่แค่เปอร์เซ็นต์
- [ ] ให้ข้อเสนอแนะเชิงบริหารที่นำไปปฏิบัติได้จริง ไม่ใช่แค่บอกว่า "ควรควบคุมค่าใช้จ่าย" ลอยๆ
- [ ] ถ้าข้อมูลไม่พอยืนยันสาเหตุ ระบุเป็นสมมติฐานอย่างตรงไปตรงมา พร้อมแนะนำวิธีตรวจสอบเพิ่มเติม
