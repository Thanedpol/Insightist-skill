# Job Description Writer

Skill นี้ช่วยฝ่าย HR, ผู้จัดการที่ต้องการรับสมัครทีม, หรือเจ้าของธุรกิจ SME แปลงข้อมูลตำแหน่งงานที่มักจะกระจัดกระจาย (โน้ตสั้นๆ, ไลน์คุยกับหัวหน้างาน, หรือ JD เก่าที่ล้าสมัย) ให้กลายเป็น Job Description ฉบับสมบูรณ์ที่มีโครงสร้างมาตรฐาน อ่านง่าย ดึงดูดผู้สมัครที่ใช่ และพร้อมนำไปโพสต์บนแพลตฟอร์มหางาน (JobsDB, LinkedIn, Facebook, เว็บบริษัท) ได้ทันที

## เมื่อไหร่ควรใช้ skill นี้

- ผู้ใช้ให้ข้อมูลตำแหน่งงานมาแบบสั้นๆ ไม่เป็นระบบ แล้วขอให้ช่วยเขียนเป็น JD ฉบับเต็ม
- ต้องการเปิดรับสมัครตำแหน่งใหม่ และยังไม่มี JD อยู่เลย
- มี JD เก่าอยู่แล้วแต่ล้าสมัย ต้องการปรับปรุงให้ทันสมัยและครบถ้วนขึ้น
- ต้องการ JD สำหรับโพสต์บนหลายแพลตฟอร์ม (เว็บบริษัท, LinkedIn, JobsDB, Facebook)
- หัวหน้าทีมอยากได้ JD ไปเสนอฝ่าย HR หรือฝ่ายบุคคลเพื่อขออนุมัติเปิดตำแหน่ง
- ต้องการเทียบเคียง JD ของตำแหน่งเดียวกันในหลายระดับ (เช่น Junior / Senior)

## ขั้นตอนการทำงาน

1. **รวบรวมข้อมูลจากผู้ใช้** — อ่านข้อมูลที่ผู้ใช้ให้มาทั้งหมด (ชื่อตำแหน่ง, แผนก, หน้าที่, คุณสมบัติ, เงินเดือน, สวัสดิการ, สถานที่ทำงาน) หากข้อมูลที่จำเป็นขาดหายไป (เช่น ไม่มีเงินเดือน หรือไม่ระบุระดับตำแหน่ง) ให้ถามผู้ใช้สั้นๆ ก่อนเขียน หรือระบุว่า "ยังไม่ระบุ — โปรดเติมภายหลัง" ในส่วนนั้นแทนการเดาเอง
2. **จัดหมวดหมู่หน้าที่งาน (Responsibilities)** — แยกหน้าที่ที่ได้รับมาออกเป็นกลุ่มตามความสำคัญ เรียงจากงานหลักไปงานรอง เขียนเป็นประโยคที่ขึ้นต้นด้วยกริยา (action verb) เช่น "วางแผน...", "ดูแล...", "ประสานงานกับ..."
3. **แยกคุณสมบัติเป็น 2 ระดับ** — คุณสมบัติที่ "ต้องมี" (Required) และ "จะพิจารณาเป็นพิเศษ" (Preferred/Nice-to-have) เพื่อไม่ให้ผู้สมัครที่มีศักยภาพหลุดกรอบเพราะเงื่อนไขที่ไม่จำเป็นจริงๆ
4. **เขียนส่วนแนะนำบริษัท/ทีมสั้นๆ** — 2-3 ประโยค ให้ผู้สมัครเห็นภาพวัฒนธรรมองค์กรและเหตุผลว่าทำไมควรมาร่วมงาน (ถ้าผู้ใช้ไม่ได้ให้ข้อมูลบริษัทมา ให้เว้นเป็นช่องว่างพร้อมหมายเหตุให้เติม)
5. **จัดรูปแบบเงินเดือนและสวัสดิการให้ชัดเจน** — ถ้าผู้ใช้ให้ช่วงเงินเดือนมา ให้ระบุตรงๆ ถ้าไม่ได้ให้มา ให้ใส่ "ตามโครงสร้างบริษัท/ตามประสบการณ์ (Negotiable)" แทนการเว้นว่าง สวัสดิการให้จัดเป็น bullet list แยกหมวด (เช่น ประกันสุขภาพ, วันลา, การพัฒนาทักษะ)
6. **ตรวจสอบภาษาให้เป็นกลางและไม่เลือกปฏิบัติ** — หลีกเลี่ยงคำที่สื่อถึงเพศ อายุ หรือลักษณะเฉพาะบุคคลที่ไม่เกี่ยวกับความสามารถในการทำงาน (เช่น หลีกเลี่ยง "ชาย/หญิงอายุไม่เกิน 30 ปี" เว้นแต่มีเหตุผลทางกฎหมายรองรับจริง)
7. **ประกอบร่างเป็น JD ฉบับสมบูรณ์** ตามโครงสร้าง Output ด้านล่าง แล้วส่งให้ผู้ใช้ตรวจทาน
8. **แจ้งเตือนเรื่องกฎหมายแรงงาน** — ปิดท้ายด้วยข้อความเตือนเสมอว่ากฎหมายแรงงาน เงื่อนไขการจ้างงาน และข้อกำหนดการประกาศรับสมัคร (เช่น ห้ามระบุเพศ/อายุในบางประเทศ) แตกต่างกันไปตามประเทศและเขตอำนาจศาล ให้ผู้ใช้ตรวจสอบกับฝ่ายกฎหมายหรือ HR ท้องถิ่นก่อนเผยแพร่จริง

## โครงสร้าง Output

```
# [ชื่อตำแหน่งงาน]

**แผนก:** [ชื่อแผนก] | **สถานที่ทำงาน:** [สถานที่ / Remote / Hybrid]
**ประเภทการจ้างงาน:** [Full-time / Part-time / Contract]
**ระดับตำแหน่ง:** [Entry / Mid / Senior / Management]
**เงินเดือน:** [ช่วงเงินเดือน หรือ "ตามโครงสร้างบริษัท/ประสบการณ์"]

## เกี่ยวกับเรา
[2-3 ประโยคแนะนำบริษัท/ทีม]

## ภาพรวมตำแหน่งงาน
[2-4 ประโยคสรุปว่าตำแหน่งนี้ทำอะไร มีความสำคัญอย่างไรต่อทีม/องค์กร]

## หน้าที่ความรับผิดชอบหลัก
- [หน้าที่ 1 — ขึ้นต้นด้วยกริยา]
- [หน้าที่ 2]
- [หน้าที่ 3]
- ...

## คุณสมบัติที่ต้องมี (Required)
- [คุณสมบัติ 1]
- [คุณสมบัติ 2]
- ...

## คุณสมบัติที่พิจารณาเป็นพิเศษ (Preferred)
- [คุณสมบัติเสริม 1]
- [คุณสมบัติเสริม 2]

## สวัสดิการ
- [สวัสดิการหมวด 1]
- [สวัสดิการหมวด 2]
- ...

## วิธีการสมัคร
[ช่องทางและเอกสารที่ต้องใช้ในการสมัคร]

---
⚠️ หมายเหตุ: กฎหมายแรงงานและข้อกำหนดการประกาศรับสมัครงานแตกต่างกันในแต่ละประเทศ กรุณาตรวจสอบกับฝ่ายกฎหมายหรือ HR ท้องถิ่นก่อนเผยแพร่ประกาศจริง
```

## ตัวอย่าง

**Input ที่ผู้ใช้ให้มา:**
> "อยากเปิดรับ Marketing Executive ทำ social media, วางแผนแคมเปญ, ต้องมีประสบการณ์ 2 ปีขึ้นไป, ใช้ Canva/Meta Ads เป็น, เงินเดือน 25,000-35,000, ทำงานที่ออฟฟิศกรุงเทพฯ"

**Output คร่าวๆ ที่ควรได้:**
JD เต็มรูปแบบตามโครงสร้างด้านบน โดย "หน้าที่ความรับผิดชอบหลัก" ขยายจาก "ทำ social media" เป็นรายการย่อยเช่น "วางแผนและจัดทำคอนเทนต์บนช่องทาง Social Media ขององค์กร", "บริหารจัดการแคมเปญโฆษณาผ่าน Meta Ads", "วิเคราะห์ผลลัพธ์แคมเปญและรายงานผู้บริหาร" ส่วนคุณสมบัติแยกเป็น Required (ประสบการณ์ 2 ปี, ใช้ Canva/Meta Ads ได้) และ Preferred (เช่น ประสบการณ์ทำ Content Video, ความรู้ SEO) พร้อมระบุเงินเดือนและปิดท้ายด้วยหมายเหตุกฎหมายแรงงานเสมอ ตัวอย่างบรรทัดในหน้าที่ความรับผิดชอบที่ปรับปรุงแล้ว เช่น "ประสานงานกับทีม Sales เพื่อวางแผนแคมเปญที่สอดคล้องกับเป้าหมายยอดขายรายไตรมาส" ซึ่งให้รายละเอียดและบริบทมากกว่าข้อความต้นฉบับที่ผู้ใช้ให้มา

## หมายเหตุเพิ่มเติมสำหรับกรณีพิเศษ

- **ตำแหน่งที่ไม่มี JD ต้นแบบมาก่อนเลย** — ถามผู้ใช้เพิ่มว่าตำแหน่งนี้รายงานตรงกับใคร และทีมมีขนาดเท่าไหร่ เพื่อให้เขียนภาพรวมตำแหน่งงาน (Overview) ได้แม่นยำขึ้น
- **ตำแหน่งระดับบริหาร (Manager ขึ้นไป)** — ควรเพิ่มหัวข้อ "ขอบเขตความรับผิดชอบเชิงกลยุทธ์" และ "จำนวนทีมที่ดูแล" แยกจากหน้าที่ปฏิบัติการทั่วไป
- **ตำแหน่งที่ทำงานแบบ Remote/Hybrid** — ระบุ time zone ที่ต้องทำงานร่วมกัน และเครื่องมือสื่อสารหลักที่ทีมใช้ ไว้ในภาพรวมตำแหน่งงานด้วย
- **หลายตำแหน่งพร้อมกัน** — หากผู้ใช้ขอ JD หลายตำแหน่งในคราวเดียว ให้แยกไฟล์/บล็อกให้ชัดเจนทีละตำแหน่ง อย่ารวมหน้าที่ของหลายตำแหน่งปนกัน
- **ตำแหน่งที่ต้องใช้ใบอนุญาตหรือวุฒิเฉพาะทาง** (เช่น บัญชี, กฎหมาย, การแพทย์) — ระบุใบอนุญาต/ใบประกอบวิชาชีพที่จำเป็นไว้ในคุณสมบัติ Required อย่างชัดเจน เพราะเป็นเงื่อนไขทางกฎหมายที่ขาดไม่ได้ในหลายประเทศ

## เกณฑ์คุณภาพ

- [ ] หน้าที่ความรับผิดชอบเขียนเป็นประโยคขึ้นต้นด้วยกริยา อ่านแล้วเห็นภาพงานจริง ไม่ใช่คำกว้างๆ ลอยๆ
- [ ] แยกคุณสมบัติ Required กับ Preferred ชัดเจน ไม่ปนกัน
- [ ] ภาษาที่ใช้เป็นกลาง ไม่มีคำที่สื่อถึงการเลือกปฏิบัติทางเพศ อายุ หรือลักษณะส่วนบุคคลที่ไม่เกี่ยวกับงาน
- [ ] ระบุเงินเดือนและสวัสดิการอย่างชัดเจน หรือระบุแนวทางแทนการเว้นว่าง
- [ ] มีหมายเหตุเตือนเรื่องกฎหมายแรงงานท้องถิ่นทุกครั้งที่ส่ง Output
- [ ] ความยาวและรายละเอียดเหมาะสมกับระดับตำแหน่ง (ตำแหน่งบริหารควรมีรายละเอียดเชิงกลยุทธ์มากกว่าตำแหน่งปฏิบัติการ)
