## 🇹🇭 ภาษาไทย

### Skill นี้สำหรับอาชีพไหน

วิศวกรโยธา วิศวกรไฟฟ้า วิศวกรเครื่องกล และวิศวกรอุตสาหการ รวมถึงสถาปนิก นักผังเมือง นักสำรวจรังวัด
และนักออกแบบผลิตภัณฑ์ ที่ต้องแปลงผลคำนวณ ผลทดสอบ หรือผลสำรวจให้เป็นรายงานทางการส่งลูกค้า ผู้บริหาร หรือหน่วยงานอนุมัติ

### ทำอะไรได้บ้าง

- เขียน **รายงานทางเทคนิควิศวกรรม** จากผลการคำนวณ ผลทดสอบวัสดุ หรือผลการตรวจสอบแบบ ให้มีโครงสร้างมาตรฐาน
- จัดทำ **การศึกษาความเป็นไปได้ (feasibility study)** พร้อมตารางเปรียบเทียบทางเลือก ข้อดี-ข้อเสีย ต้นทุนและความเสี่ยง
- เตรียม **เอกสารประกอบการทบทวนแบบ (design review)** และรายงานประกอบการยื่นขออนุญาต
- ระบุ **สมมติฐาน ข้อจำกัด และมาตรฐานอ้างอิง** อย่างโปร่งใส ตรวจสอบย้อนกลับได้
- สรุป **ผลการวิเคราะห์เทียบเกณฑ์ค่ายอมรับได้** ในรูปตาราง ผ่าน/ไม่ผ่าน
- สรุปผลสำรวจภาคสนามหรือรายงานทดสอบต้นแบบ (prototype test report) ด้วยภาษาที่คนนอกสายเทคนิคก็อ่านเข้าใจ

### ตัวอย่างคำสั่ง

- "ช่วยเขียนรายงานวิศวกรรม สรุปผลตรวจกำลังรับน้ำหนักคานอาคารเก่าก่อนต่อเติมชั้น 3"
- "ทำ feasibility study โครงการติดตั้งโซลาร์รูฟบนหลังคาโรงงาน"
- "สรุปผลการทดสอบต้นแบบชิ้นงานนี้เป็น technical report เสนอผู้บริหาร"

### สิ่งที่จะได้รับ

รายงานทางเทคนิค 7 ส่วน — (1) วัตถุประสงค์และขอบเขต (2) ข้อมูลนำเข้าและมาตรฐานอ้างอิง (3) สมมติฐานและข้อจำกัด
(4) ผลการวิเคราะห์/คำนวณเทียบเกณฑ์ (5) การประเมินทางเลือก (ถ้ามี) (6) สรุปผลและข้อเสนอแนะ พร้อมจุดที่ต้องให้ผู้มีใบอนุญาตลงนามรับรอง
(7) รายการภาคผนวก

### ขอบเขตและข้อควรระวัง

- ไม่เดาค่ามาตรฐาน ตัวเลขเกณฑ์ หรือรหัสมาตรฐานที่ไม่แน่ใจ จะระบุให้ตรวจสอบกับแหล่งอ้างอิงแทน
- แยกข้อเท็จจริง (ผลคำนวณ/ทดสอบ) ออกจากความเห็นและข้อเสนอแนะอย่างชัดเจน
- ผลงานเป็นร่างรายงาน **ต้องให้วิศวกรหรือผู้เชี่ยวชาญที่มีใบอนุญาตตรวจสอบและลงนามรับรอง** ก่อนนำไปใช้จริง
- ไม่ฟันธงเกินขอบเขตข้อมูลที่มี หากข้อมูลไม่ครบจะระบุไว้ตรงไปตรงมา

## 🇬🇧 English

### Who is this skill for

Civil, electrical, mechanical and industrial engineers, as well as architects, urban planners, land surveyors
and product designers who need to turn calculations, test results or survey data into a formal report for
clients, management or approving authorities.

### What it can do

- Write an **engineering technical report** from calculations, material tests or design checks, using a standard structure
- Prepare a **feasibility study** with a side-by-side comparison of options, pros and cons, cost and risk
- Draft **design review documents** and supporting reports for permit applications
- State **assumptions, limitations and reference standards** openly so every result can be traced
- Present **results against allowable values** in a clear pass/fail table
- Summarise field surveys or prototype test reports in language that non-technical stakeholders can follow

### Example prompts

- "Write an engineering report on whether the existing beams can carry a third-floor extension."
- "Prepare a feasibility study for a rooftop solar installation on our factory."
- "Turn these prototype test results into a technical report for management."

### What you get

A technical report in seven sections: (1) objective and scope, (2) input data and reference standards,
(3) assumptions and limitations, (4) analysis or calculation results against criteria, (5) option assessment (if needed),
(6) conclusions and recommendations, including the points a licensed professional must certify, and (7) a list of appendices.

### Scope and limitations

- Never guesses standard values, thresholds or code numbers; flags them for checking against the relevant source instead
- Keeps facts (calculations and test results) clearly separate from opinions and recommendations
- The output is a draft: **a licensed engineer or specialist must review and sign it off** before real-world use
- Does not draw conclusions beyond the available data, and states openly where information is missing
