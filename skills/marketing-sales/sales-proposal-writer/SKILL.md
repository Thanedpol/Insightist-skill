# Sales Proposal Writer

Skill นี้ช่วยแปลงข้อมูลดิบ (ลูกค้าคือใคร มีปัญหา/โจทย์อะไร เราจะช่วยแก้อย่างไร และราคาเท่าไหร่) ให้กลายเป็นใบเสนอราคา/proposal ขายงานที่มีโครงสร้างชัดเจน อ่านแล้วน่าเชื่อถือ และพร้อมส่งให้ลูกค้าตัดสินใจได้ทันที เหมาะสำหรับฟรีแลนซ์ เอเจนซี่ ทีมขาย B2B หรือใครก็ตามที่ต้องส่งข้อเสนอราคาให้ลูกค้าเป็นประจำ

## เมื่อไหร่ควรใช้ skill นี้

- ผู้ใช้มีข้อมูลลูกค้า + โจทย์ + ราคา แล้วอยากให้จัดเป็นเอกสารเสนอขายที่เป็นทางการ
- ต้องส่ง quotation/ใบเสนอราคาให้ลูกค้าใหม่หรือลูกค้าเก่าที่ต่อยอดงาน
- ต้องเปรียบเทียบแพ็กเกจ/ตัวเลือกราคาหลายระดับ (เช่น Basic / Standard / Premium) ในเอกสารเดียว
- ต้องการปรับ proposal เดิมให้ดูเป็นมืออาชีพขึ้น หรือปรับโทนให้เหมาะกับลูกค้าองค์กร
- ทีมขายต้องส่ง proposal จำนวนมากและต้องการ template ที่ทำซ้ำได้เร็ว รักษามาตรฐานเดียวกัน

## ขั้นตอนการทำงาน

1. **รวบรวมข้อมูลจากผู้ใช้** — ถ้าข้อมูลที่ให้มายังไม่ครบ ให้ถามเพิ่มเฉพาะจุดที่ขาดจริงๆ (อย่าถามทุกข้อถ้าเดาได้จากบริบท):
   - ชื่อลูกค้า/บริษัท และผู้ติดต่อ
   - โจทย์หรือปัญหาที่ลูกค้าต้องการแก้ (pain point / เป้าหมาย)
   - ขอบเขตงานที่จะทำ (scope of work) และ deliverable
   - ราคาและเงื่อนไขการชำระเงิน
   - ระยะเวลาทำงาน/กำหนดส่งงาน
   - เงื่อนไขอื่นๆ เช่น จำนวนรอบแก้ไข, วันหมดอายุของใบเสนอราคา
2. **วิเคราะห์โจทย์ให้ชัดก่อนเขียน** — สรุปว่าลูกค้าต้องการแก้ปัญหาอะไรจริงๆ (ไม่ใช่แค่ทวนสิ่งที่ลูกค้าพูด) เพื่อใช้เปิดเอกสารด้วยความเข้าใจปัญหา ไม่ใช่เปิดด้วยการขายของ
3. **จัดโครงสร้างขอบเขตงานให้เป็นระบบ** — แตกงานเป็นหัวข้อย่อยที่จับต้องได้ ระบุ deliverable ที่ชัดเจนในแต่ละหัวข้อ หลีกเลี่ยงคำกว้างๆ ที่ตีความได้หลายแบบ
4. **นำเสนอราคาให้ตัดสินใจง่าย** — ถ้ามีราคาเดียวให้แสดงชัดเจนพร้อมสิ่งที่ได้ ถ้ามีหลายแพ็กเกจให้จัดเป็นตารางเปรียบเทียบ และเน้น (highlight) ตัวเลือกที่แนะนำ
5. **ใส่เหตุผลว่าทำไมควรเลือกเรา** — เชื่อมโยงกลับไปที่โจทย์ของลูกค้า (ไม่ใช่ list ผลงานทั่วไปที่ไม่เกี่ยวกับโจทย์นี้) ใส่เฉพาะข้อมูลที่ผู้ใช้ให้มาหรือยืนยันแล้ว ห้ามสร้างผลงาน/ตัวเลข/รีวิวที่ผู้ใช้ไม่ได้ให้มา
6. **ระบุขั้นตอนถัดไปให้ชัด (Call to Action)** — บอกว่าลูกค้าต้องทำอะไรต่อเพื่อเริ่มงาน (เซ็นเอกสาร, โอนมัดจำ, นัดประชุม) พร้อมวันหมดอายุของราคาที่เสนอ
7. **ตรวจทานโทนและความสมบูรณ์** — อ่านทวนให้แน่ใจว่าโทนเป็นทางการเหมาะกับลูกค้าองค์กร ไม่มีข้อมูลขัดแย้งกัน ตัวเลขราคารวมถูกต้อง และไม่มีช่องว่าง [ ] ที่ยังไม่ได้กรอกหลงเหลืออยู่

## โครงสร้าง Output

```
# ใบเสนอราคา / Proposal: [ชื่อโปรเจกต์]

เรียน [ชื่อผู้ติดต่อ] / [ชื่อบริษัทลูกค้า]
วันที่: [วันที่ออกเอกสาร]        เลขที่เอกสาร: [เลขอ้างอิง]
ใบเสนอราคานี้มีผลถึงวันที่: [วันหมดอายุ]

## 1. ความเข้าใจโจทย์ของลูกค้า
[สรุปปัญหา/เป้าหมายของลูกค้า 3-5 บรรทัด แสดงให้เห็นว่าเข้าใจสถานการณ์จริง]

## 2. แนวทางและขอบเขตงานที่นำเสนอ (Scope of Work)
- หัวข้องานที่ 1: [รายละเอียด + deliverable]
- หัวข้องานที่ 2: [รายละเอียด + deliverable]
- หัวข้องานที่ 3: [รายละเอียด + deliverable]

## 3. ระยะเวลาดำเนินงาน
| ขั้นตอน | ระยะเวลา | Deliverable |
|---|---|---|
| [ขั้นตอน] | [ระยะเวลา] | [สิ่งที่ส่งมอบ] |

## 4. อัตราค่าบริการ
| แพ็กเกจ/รายการ | รายละเอียด | ราคา |
|---|---|---|
| [ชื่อแพ็กเกจ] | [สิ่งที่ได้] | [ราคา] |

เงื่อนไขการชำระเงิน: [เช่น มัดจำ 50% ก่อนเริ่มงาน ส่วนที่เหลือชำระเมื่องานเสร็จ]

## 5. ทำไมควรเลือกเรา
[เหตุผล 3-4 ข้อ เชื่อมกับโจทย์ของลูกค้าโดยตรง]

## 6. เงื่อนไขเพิ่มเติม
- จำนวนรอบแก้ไข: [ระบุ]
- สิ่งที่ไม่รวมในราคานี้ (ถ้ามี): [ระบุ]
- อื่นๆ: [ระบุ]

## 7. ขั้นตอนถัดไป
[สิ่งที่ลูกค้าต้องทำเพื่อเริ่มงาน พร้อมช่องทางติดต่อกลับ]

ขอบคุณที่ให้โอกาสพิจารณาข้อเสนอนี้
[ชื่อผู้เสนอ / บริษัท / ช่องทางติดต่อ]
```

## ตัวอย่าง

**Input:** "ลูกค้าคือร้านกาแฟ 3 สาขา อยากได้ระบบ POS ใหม่เพราะระบบเดิมล่มบ่อย งบประมาณ 80,000 บาท ทำเสร็จใน 6 สัปดาห์ ต้องการรายงานยอดขายแบบเรียลไทม์"

**Output ที่ควรได้:** เอกสาร proposal ที่เปิดด้วยการสรุปปัญหา "ระบบ POS เดิมล่มบ่อยกระทบการขายหน้าร้าน 3 สาขา" ตามด้วย scope งานแตกเป็นหัวข้อ เช่น ติดตั้งระบบ POS ใหม่ 3 สาขา, ระบบรายงานยอดขายเรียลไทม์, อบรมพนักงาน, ตารางเวลา 6 สัปดาห์แบ่งเป็น milestone, ราคารวม 80,000 บาทพร้อมเงื่อนไขมัดจำ, เหตุผลที่ควรเลือกใช้บริการ และปิดท้ายด้วย CTA ให้ลูกค้ายืนยันเริ่มงาน

## เกณฑ์คุณภาพ

- [ ] ราคาที่แสดงในเอกสารตรงกับตัวเลขที่ผู้ใช้ให้มา บวกลบรวมถูกต้อง ไม่มีการสร้างตัวเลขขึ้นเอง
- [ ] ขอบเขตงานเขียนเป็น deliverable ที่จับต้องได้ ไม่ใช่คำกว้างๆ ที่ตีความได้หลายทาง
- [ ] เปิดเอกสารด้วยความเข้าใจปัญหาลูกค้า ไม่ใช่เปิดด้วยการขายของทันที
- [ ] มี Call to Action และวันหมดอายุของราคาที่ชัดเจน
- [ ] ไม่มีช่องว่าง [ ] หรือข้อมูลค้างที่ยังไม่ได้กรอกในเอกสารสุดท้าย
- [ ] โทนภาษาเหมาะสมกับลูกค้าเป้าหมาย (ทางการสำหรับองค์กร เป็นกันเองสำหรับลูกค้ารายย่อย)
