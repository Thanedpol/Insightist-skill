# Customer Service Call Script and Response Writer

Skill นี้ช่วยเสมียนบริการลูกค้าในทุกหน้างาน ตั้งแต่เคาน์เตอร์ธนาคาร คอลเซ็นเตอร์ เคาน์เตอร์ต้อนรับ ไปจนถึงจุดขายตั๋วและศูนย์ข้อมูลนักท่องเที่ยว ให้มีสคริปต์และเทมเพลตคำตอบที่พร้อมใช้ทันที สื่อสารชัดเจน สุภาพ และแก้ปัญหาลูกค้าได้ตรงจุด โดยยังคงความเป็นธรรมชาติไม่เหมือนอ่านบทท่องจำ

## เมื่อไหร่ควรใช้ skill นี้

- พนักงานคอลเซ็นเตอร์ต้องการสคริปต์รับสายตั้งแต่เปิดสายจนปิดสาย สำหรับสถานการณ์ต่างๆ
- พนักงานเคาน์เตอร์ธนาคารหรือพนักงานต้อนรับต้องการชุดคำตอบมาตรฐานสำหรับคำถามที่ลูกค้าถามซ้ำบ่อย
- พนักงานขายตั๋วหรือเจ้าหน้าที่ข้อมูลนักท่องเที่ยวต้องเตรียมคำตอบเรื่องราคา ตารางเวลา หรือเงื่อนไขการคืนเงิน
- ต้องร่างคำตอบจัดการข้อร้องเรียนที่ลูกค้าไม่พอใจ ทั้งทางโทรศัพท์ อีเมล หรือแชท
- ต้องการทำคู่มือ FAQ ให้ทีมบริการลูกค้าใช้ตอบคำถามให้เป็นมาตรฐานเดียวกัน

## ขั้นตอนการทำงาน

### 1. ระบุช่องทางและสถานการณ์
สอบถาม/ระบุ: ช่องทางสื่อสาร (โทรศัพท์/แชท/หน้าเคาน์เตอร์/อีเมล), ประเภทสถานการณ์ (สอบถามข้อมูล/ร้องเรียน/ขอความช่วยเหลือฉุกเฉิน), และอารมณ์ของลูกค้าที่คาดว่าจะเจอ (ปกติ/หงุดหงิด/โกรธ)

### 2. โครงสร้างสคริปต์การรับสาย/ต้อนรับ
สร้างสคริปต์ตามลำดับ: เปิดการสนทนา (แนะนำตัว+หน่วยงาน) → ยืนยันตัวตน/ความต้องการลูกค้า → ฟังและทวนความต้องการ → ให้ข้อมูล/แก้ไขปัญหา → สรุปสิ่งที่ตกลง → ปิดการสนทนาอย่างสุภาพ

### 3. เขียนเทมเพลตคำตอบ FAQ
- จัดกลุ่มคำถามที่พบบ่อยตามหัวข้อ (เช่น ค่าธรรมเนียม, เวลาทำการ, ขั้นตอนการขอคืนเงิน, เอกสารที่ต้องใช้)
- แต่ละคำตอบต้องสั้น ตรงประเด็น ให้ข้อมูลที่ถูกต้อง และมีทางเลือกถัดไปเสมอ (เช่น ช่องทางติดต่อเพิ่มเติมถ้าคำตอบยังไม่ครอบคลุม)

### 4. ร่างคำตอบจัดการข้อร้องเรียน
ใช้โครงสร้าง: รับฟัง/ขอบคุณที่แจ้ง → แสดงความเข้าใจในความไม่สะดวก (ไม่ใช่การยอมรับผิดล่วงหน้า) → อธิบายสิ่งที่จะดำเนินการ → ให้กรอบเวลาที่ชัดเจน → ช่องทางติดตามผล

### 5. ปรับน้ำเสียงตามสถานการณ์
- ลูกค้าปกติ: เป็นมิตร กระชับ
- ลูกค้าหงุดหงิด/โกรธ: ใจเย็น ไม่โต้แย้ง ใช้คำที่ลดความตึงเครียด เช่น "เข้าใจครับว่าเรื่องนี้สร้างความไม่สะดวก" แทนการแก้ตัว
- หลีกเลี่ยงคำปฏิเสธห้วนๆ เช่น "ทำไม่ได้" ให้เสนอทางเลือกแทนเสมอเมื่อเป็นไปได้

### 6. ใส่จุดที่ต้องเช็คข้อเท็จจริงกับหน่วยงาน
- ระบุชัดเจนว่าตัวเลข เงื่อนไข หรือนโยบายใดในสคริปต์ต้อง "ยืนยันกับหน่วยงาน/ฝ่ายที่เกี่ยวข้องก่อนใช้จริง" โดยเฉพาะเรื่องราคา อัตราดอกเบี้ย หรือกฎระเบียบที่เปลี่ยนแปลงได้

### 7. ทบทวนความสอดคล้องกับนโยบายองค์กร
- ตรวจว่าคำตอบไม่ขัดกับนโยบายที่ผู้ใช้ให้มา และไม่มีการให้สัญญาที่เกินอำนาจของพนักงาน (เช่น รับปากคืนเงินโดยไม่ผ่านกระบวนการอนุมัติ)

## โครงสร้าง Output

```
=== สคริปต์/เทมเพลต: [ชื่อสถานการณ์] ===
ช่องทาง: [โทรศัพท์/แชท/หน้าเคาน์เตอร์]

1) เปิดการสนทนา
[บทพูด]

2) ยืนยันความต้องการ
[บทพูด/คำถามที่ควรถาม]

3) เนื้อหาหลัก / คำตอบ FAQ
Q: [คำถาม]
A: [คำตอบ]
(ทำซ้ำตามจำนวนหัวข้อ)

4) กรณีร้องเรียน (ถ้ามี)
- รับฟัง: [บทพูด]
- แสดงความเข้าใจ: [บทพูด]
- แนวทางดำเนินการ: [บทพูด + กรอบเวลา]

5) ปิดการสนทนา
[บทพูด]

หมายเหตุ: [รายการที่ต้องยืนยันข้อเท็จจริง/นโยบายกับหน่วยงานก่อนใช้จริง]
```

## ตัวอย่าง

**Input:** "ทำสคริปต์คอลเซ็นเตอร์ธนาคาร สำหรับลูกค้าโทรมาถามว่าทำไมโดนหักค่าธรรมเนียมรักษาบัญชี"

**Output (คร่าวๆ):**
```
1) เปิดการสนทนา
"สวัสดีค่ะ ธนาคาร [ชื่อ] ยินดีให้บริการค่ะ ดิฉัน [ชื่อพนักงาน] รบกวนขอทราบชื่อ-นามสกุลและเลขบัญชีเพื่อยืนยันตัวตนค่ะ"

2) ยืนยันความต้องการ
"ขอบคุณค่ะ ทราบว่าลูกค้าต้องการสอบถามเรื่องค่าธรรมเนียมรักษาบัญชีใช่ไหมคะ"

3) เนื้อหาหลัก
Q: ทำไมถึงถูกหักค่าธรรมเนียมรักษาบัญชี
A: "ค่าธรรมเนียมนี้จะเรียกเก็บเมื่อยอดเงินคงเหลือในบัญชีต่ำกว่ายอดขั้นต่ำที่กำหนดในเดือนนั้นๆ ค่ะ (ยอดขั้นต่ำและอัตราจริงต้องยืนยันกับฝ่ายผลิตภัณฑ์เงินฝากก่อนแจ้งลูกค้า)"

5) ปิดการสนทนา
"มีอะไรให้ช่วยเหลือเพิ่มเติมไหมคะ ขอบคุณที่ใช้บริการค่ะ"
```

## เกณฑ์คุณภาพ

- [ ] สคริปต์ครบทุกช่วง ตั้งแต่เปิดจนถึงปิดการสนทนา
- [ ] น้ำเสียงเหมาะสมกับสถานการณ์ (ปกติ/ร้องเรียน/ลูกค้าไม่พอใจ)
- [ ] คำตอบ FAQ กระชับ ตรงประเด็น และเสนอทางเลือกถัดไปเสมอเมื่อตอบไม่ได้ทันที
- [ ] ไม่ให้สัญญาหรือระบุตัวเลข/นโยบายที่เกินอำนาจโดยไม่ทำเครื่องหมายให้ตรวจสอบก่อน
- [ ] ไม่สร้างตัวเลขค่าธรรมเนียม อัตราดอกเบี้ย หรือเงื่อนไขที่ผู้ใช้ไม่ได้ให้มาขึ้นเอง ต้องระบุว่าให้ยืนยันกับหน่วยงานก่อนใช้จริง
- [ ] มีจุดที่ระบุชัดว่ารายการใดต้องเช็คกับหน่วยงานก่อนนำไปใช้งานจริง
