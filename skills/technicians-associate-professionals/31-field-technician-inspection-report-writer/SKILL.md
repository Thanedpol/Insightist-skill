# Field Technician Inspection Report Writer

Skill นี้ช่วยแปลงบันทึกจากการลงพื้นที่ตรวจสอบ การควบคุมงาน หรือการตรวจสอบคุณภาพ ให้กลายเป็นรายงานที่มีโครงสร้างชัดเจน อ่านง่าย และใช้เป็นหลักฐานอ้างอิงได้ เหมาะกับงานสายเทคนิควิทยาศาสตร์และวิศวกรรมที่ต้องบันทึกสิ่งที่พบหน้างานอย่างเป็นระบบ ไม่ใช่การเขียนบรรยายลอยๆ

## เมื่อไหร่ควรใช้ skill นี้

- ช่างเทคนิคโยธา/ไฟฟ้า/อิเล็กทรอนิกส์ ลงพื้นที่ตรวจสอบงานก่อสร้างหรือระบบไฟฟ้า แล้วต้องการสรุปเป็นรายงาน
- ผู้ควบคุมงานโรงงาน (production supervisor) หรือผู้ควบคุมงานเหมือง ต้องการบันทึกผลตรวจรอบกะหรือรอบวัน
- ช่างเทคนิคควบคุมคุณภาพ (QC technician) ตรวจสอบชิ้นงาน/ล็อตผลิต แล้วต้องสรุปผล pass/fail พร้อมเหตุผล
- ช่างเขียนแบบหรือช่างเทคนิคเคมี ต้องการบันทึกผลการตรวจสอบตัวอย่างหรือแบบก่อสร้างเทียบสเปก
- นายเรือ/ต้นหน หรือนักบิน ต้องการบันทึกรายงานตรวจสภาพเครื่องมือ/ยานพาหนะก่อนปฏิบัติงาน (pre-operation check)

## ขั้นตอนการทำงาน

### 1. รวบรวมข้อมูลพื้นฐานของการตรวจ
ระบุให้ครบก่อนเริ่มเขียน: วันที่/เวลา, สถานที่หรือหมายเลขไซต์งาน, ผู้ตรวจ, มาตรฐานหรือสเปกอ้างอิง (ถ้ามี เช่น แบบก่อสร้าง, ISO, SOP โรงงาน), ขอบเขตของการตรวจครั้งนี้

### 2. จัดหมวดรายการตรวจ (checklist items)
แบ่งสิ่งที่ตรวจเป็นหมวดตามลักษณะงาน เช่น โครงสร้าง / ระบบไฟฟ้า / ความปลอดภัย / เครื่องจักร / คุณภาพชิ้นงาน — แต่ละหมวดระบุรายการย่อยที่ตรวจจริง

### 3. บันทึกผลตรวจแต่ละรายการอย่างเป็นกลาง
สำหรับแต่ละรายการ ระบุ: สิ่งที่พบ (observation), ผลเทียบเกณฑ์ (ผ่าน/ไม่ผ่าน/ต้องติดตาม), และหลักฐานประกอบถ้ามี (ภาพถ่าย, ค่าที่วัดได้, หมายเลขชิ้นงาน) — เขียนตามข้อเท็จจริงที่ได้รับมา ห้ามเติมค่าตัวเลขหรือผลวัดที่ผู้ใช้ไม่ได้ให้มา

### 4. ระบุข้อบกพร่องหรือความเสี่ยงที่พบ (non-conformance)
แยกความรุนแรงเป็นระดับ เช่น วิกฤต (critical) / สำคัญ (major) / เล็กน้อย (minor) พร้อมตำแหน่งที่พบและผลกระทบที่อาจเกิดขึ้น

### 5. เสนอข้อแนะนำแก้ไข (corrective action)
ระบุสิ่งที่ควรทำต่อ ผู้รับผิดชอบ (ถ้าทราบ) และกรอบเวลาที่ควรแก้ไข โดยแยกให้ชัดระหว่าง "ข้อเท็จจริงที่พบ" กับ "ข้อเสนอแนะของผู้ตรวจ"

### 6. สรุปผลรวมของการตรวจ
สรุปว่าโดยรวมงาน/ระบบ/ชิ้นงานนี้ผ่านเกณฑ์หรือไม่ มีเงื่อนไขอะไรก่อนอนุมัติให้ดำเนินงานต่อหรือไม่

### 7. จัดรูปแบบให้พร้อมส่งต่อ
จัดเรียงเป็นรายงานที่ผู้บังคับบัญชา ลูกค้า หรือหน่วยงานกำกับดูแลอ่านแล้วเข้าใจได้ทันที ไม่ต้องถามกลับ

## โครงสร้าง Output

```
=== รายงานตรวจสอบหน้างาน / Inspection Report ===
วันที่ตรวจ: [วัน/เดือน/ปี เวลา]
สถานที่/ไซต์งาน: [ชื่อ/รหัส]
ผู้ตรวจ: [ชื่อ-ตำแหน่ง]
มาตรฐาน/สเปกอ้างอิง: [ถ้ามี]
ขอบเขตการตรวจ: [สรุปสั้นๆ]

1) รายการตรวจและผล
   หมวด: [เช่น โครงสร้าง]
   - รายการ: [...] | ผล: ผ่าน/ไม่ผ่าน/ติดตาม | สิ่งที่พบ: [...] | หลักฐาน: [...]

2) ข้อบกพร่องที่พบ (Non-conformance)
   - ระดับ: [วิกฤต/สำคัญ/เล็กน้อย] | ตำแหน่ง: [...] | รายละเอียด: [...] | ผลกระทบ: [...]

3) ข้อเสนอแนะแก้ไข (Corrective Action)
   - สิ่งที่ควรทำ: [...] | ผู้รับผิดชอบ: [...] | กรอบเวลา: [...]

4) สรุปผลรวม
   ผลการตรวจโดยรวม: [ผ่าน/ไม่ผ่าน/ผ่านแบบมีเงื่อนไข]
   เงื่อนไขก่อนดำเนินงานต่อ (ถ้ามี): [...]
```

## ตัวอย่าง

**Input:** ช่างเทคนิคไฟฟ้าลงตรวจตู้ MDB ที่ไซต์อาคาร B ชั้น 3 พบสายไฟจุดหนึ่งมีรอยไหม้เล็กน้อยบริเวณขั้วต่อ เบรกเกอร์อื่นทำงานปกติ

**Output (คร่าวๆ):**
- รายการตรวจ: ตู้ MDB ชั้น 3 อาคาร B | ผล: ไม่ผ่าน (บางส่วน) | สิ่งที่พบ: พบรอยไหม้เล็กน้อยที่ขั้วต่อสายไฟเส้นหนึ่ง สันนิษฐานว่าเกิดจากขั้วต่อหลวม
- ข้อบกพร่อง: ระดับสำคัญ (major) — ตำแหน่งขั้วต่อสาย L2 ในตู้ MDB ชั้น 3 หากปล่อยไว้อาจเสี่ยงความร้อนสะสมและไฟฟ้าลัดวงจร
- ข้อเสนอแนะ: ให้ช่างไฟฟ้าตรวจซ้ำและขันแน่น/เปลี่ยนขั้วต่อภายใน 3 วันทำการ ก่อนใช้งานตู้เต็มโหลด
- สรุปผลรวม: ผ่านแบบมีเงื่อนไข — ต้องแก้ไขจุดขั้วต่อก่อนปิดงานตรวจ

## เกณฑ์คุณภาพ

- [ ] มีข้อมูลพื้นฐานครบ (วันที่ สถานที่ ผู้ตรวจ มาตรฐานอ้างอิง)
- [ ] แยกชัดเจนระหว่าง "ข้อเท็จจริงที่พบหน้างาน" กับ "ความเห็น/ข้อเสนอแนะของผู้ตรวจ"
- [ ] จัดระดับความรุนแรงของข้อบกพร่องอย่างสมเหตุสมผล ไม่ประเมินเกินจริงหรือมองข้าม
- [ ] ไม่ใส่ค่าตัวเลข ผลวัด หรือภาพหลักฐานที่ผู้ใช้ไม่ได้ให้ข้อมูลมา
- [ ] มีข้อเสนอแนะแก้ไขที่ปฏิบัติได้จริง ไม่ใช่คำแนะนำทั่วไปที่ไม่เจาะจง
- [ ] สรุปผลรวมชัดเจนว่าผ่าน/ไม่ผ่าน/ผ่านแบบมีเงื่อนไข
