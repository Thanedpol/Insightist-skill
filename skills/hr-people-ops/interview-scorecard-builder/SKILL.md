# Interview Scorecard Builder

Skill นี้ช่วยผู้สัมภาษณ์ (Hiring Manager, HR, หรือทีมที่ร่วมสัมภาษณ์) สร้างเครื่องมือให้คะแนนผู้สมัครงานที่เป็นมาตรฐาน อิงตาม competency ที่ตำแหน่งงานนั้นต้องการจริงๆ ลดอคติส่วนตัว (bias) ในการตัดสินใจ และทำให้ทีมสัมภาษณ์หลายคนสามารถเปรียบเทียบผลการประเมินผู้สมัครแต่ละคนได้อย่างเป็นธรรมและมีหลักฐานอ้างอิง

## เมื่อไหร่ควรใช้ skill นี้

- กำลังจะสัมภาษณ์ผู้สมัครตำแหน่งใหม่ และยังไม่มีเกณฑ์ให้คะแนนที่เป็นมาตรฐาน
- มีทีมสัมภาษณ์หลายคน (panel interview) และต้องการเกณฑ์กลางเพื่อเปรียบเทียบผลได้
- ต้องการลดอคติในการตัดสินใจรับสมัคร (unconscious bias) ด้วยเกณฑ์ที่วัดผลได้ชัดเจน
- ต้องการออกแบบคำถามสัมภาษณ์เชิงพฤติกรรม (behavioral) หรือเชิงสถานการณ์ (situational) ที่เจาะจงกับ competency ที่ต้องการ
- ต้องการปรับปรุง scorecard เดิมที่มีอยู่ให้ครอบคลุมและวัดผลได้ดีขึ้น
- ต้องการเปรียบเทียบผู้สมัครหลายคนสำหรับตำแหน่งเดียวกันอย่างเป็นระบบ

## ขั้นตอนการทำงาน

1. **ยืนยันตำแหน่งงานและ Competency ที่ต้องการวัด** — สอบถามหรือสรุปจากข้อมูลที่ผู้ใช้ให้มา: ชื่อตำแหน่ง, ระดับ (Junior/Senior/Manager), และ competency หลักที่จำเป็น (เช่น Technical Skill, Communication, Problem Solving, Leadership, Culture Fit) โดยทั่วไปแนะนำ 4-6 competency ต่อ 1 scorecard เพื่อไม่ให้สัมภาษณ์นานเกินไปหรือประเมินหลวมเกินไป
2. **นิยาม Competency แต่ละตัวให้ชัดเจน** — เขียนคำจำกัดความสั้นๆ ว่า competency นั้นหมายถึงอะไรในบริบทของตำแหน่งนี้ เพื่อให้ผู้สัมภาษณ์ทุกคนเข้าใจตรงกัน
3. **ออกแบบคำถามสัมภาษณ์ต่อ Competency** — สร้างคำถามอย่างน้อย 1-2 ข้อต่อ competency โดยเน้นคำถามเชิงพฤติกรรม (Behavioral: "เล่าครั้งที่คุณ...") หรือเชิงสถานการณ์ (Situational: "ถ้าคุณเจอสถานการณ์...") มากกว่าคำถามปลายปิดที่ตอบใช่/ไม่ใช่
4. **กำหนดระดับคะแนนที่มีคำอธิบายชัดเจน (Anchored Rating Scale)** — ใช้สเกล 1-5 โดยแต่ละระดับมีคำอธิบายพฤติกรรมที่จับต้องได้ (behaviorally anchored) ไม่ใช่แค่ตัวเลขลอยๆ เช่น 1 = ไม่แสดงพฤติกรรมที่ต้องการเลย, 5 = แสดงพฤติกรรมที่ต้องการอย่างโดดเด่นเกินความคาดหวัง
5. **กำหนดน้ำหนักคะแนน (ถ้าจำเป็น)** — ถ้าบาง competency สำคัญกว่าตัวอื่นสำหรับตำแหน่งนี้ ให้เสนอการถ่วงน้ำหนัก (weighting) เช่น Technical Skill 40%, Communication 20% เป็นต้น โดยอธิบายเหตุผลสั้นๆ
6. **เพิ่มช่องบันทึกหลักฐานเชิงคุณภาพ** — ทุก competency ต้องมีช่องให้ผู้สัมภาษณ์จดบันทึกคำตอบ/ตัวอย่างที่ผู้สมัครยกมา ไม่ใช่แค่ตัวเลขคะแนนอย่างเดียว เพื่อใช้อ้างอิงตอนเปรียบเทียบกับผู้สมัครคนอื่น
7. **สรุปเป็น Scorecard ฉบับสมบูรณ์** ตามโครงสร้าง Output ด้านล่าง พร้อมช่องสรุปผลรวมและคำแนะนำขั้นตอนถัดไป (Advance / Hold / Reject)
8. **แจ้งเตือนเรื่องกฎหมายและความเป็นธรรมในการจ้างงาน** — ปิดท้ายด้วยข้อความเตือนเสมอว่าคำถามสัมภาษณ์และเกณฑ์ประเมินต้องไม่ละเมิดกฎหมายแรงงานหรือกฎหมายต่อต้านการเลือกปฏิบัติของแต่ละประเทศ (เช่น ห้ามถามเรื่องส่วนตัวที่ไม่เกี่ยวกับงานในบางเขตอำนาจศาล) ให้ผู้ใช้ตรวจสอบกับฝ่ายกฎหมายหรือ HR ท้องถิ่นก่อนใช้จริง

## ตัวอย่าง

**Input ที่ผู้ใช้ให้มา:**
> "ต้องการ scorecard สำหรับตำแหน่ง Software Engineer (Mid-level) ประเมิน 4 ด้าน: Technical Skill, Problem Solving, Communication, Culture Fit"

**Output คร่าวๆ ที่ควรได้:**
Scorecard เต็มรูปแบบตามโครงสร้างด้านบน โดยแต่ละ competency มีนิยามเจาะจง เช่น "Technical Skill = ความสามารถในการเขียนโค้ดที่ถูกต้อง มีประสิทธิภาพ และเลือกใช้เทคโนโลยีเหมาะสมกับปัญหา" พร้อมคำถาม เช่น "เล่าถึงปัญหาทางเทคนิคที่ยากที่สุดที่คุณเคยแก้ และวิธีที่คุณแก้ปัญหานั้น" มีน้ำหนักคะแนนที่เสนอ เช่น Technical Skill 40%, Problem Solving 30%, Communication 20%, Culture Fit 10% พร้อมช่องบันทึกหลักฐานและสรุปผลรวมท้ายตาราง

## หมายเหตุเพิ่มเติมสำหรับกรณีพิเศษ

- **Panel Interview หลายคน** — แนะนำให้ผู้สัมภาษณ์แต่ละคนกรอก scorecard แยกกันก่อน แล้วค่อยมาเทียบคะแนนพร้อมกันในที่ประชุม (calibration session) เพื่อลดผลกระทบจากความเห็นของคนที่พูดก่อนหรือมีตำแหน่งสูงกว่า (anchoring bias)
- **ตำแหน่งที่ต้องสัมภาษณ์หลายรอบ** — ทำ scorecard แยกตามรอบ เช่น รอบ HR Screening เน้น Culture Fit/Communication ส่วนรอบ Technical เน้น Technical Skill/Problem Solving เพื่อไม่ให้ประเมินซ้ำซ้อนกัน
- **ตำแหน่งที่ไม่มีคำตอบถูกผิดชัดเจน (เช่นสาย Creative)** — ให้เพิ่มตัวอย่างผลงาน (portfolio) เป็นส่วนหนึ่งของหลักฐานประกอบคะแนน ไม่ใช้แค่คำตอบในห้องสัมภาษณ์อย่างเดียว
- **การเปรียบเทียบผู้สมัครหลายคน** — แนะนำให้สรุปคะแนนรวมของผู้สมัครทุกคนไว้ในตารางเดียวแยกต่างหาก เพื่อให้ทีมตัดสินใจเห็นภาพเปรียบเทียบได้ง่าย
- **ผู้สัมภาษณ์มือใหม่** — แนบตัวอย่างคำตอบระดับ 3 (ตรงมาตรฐาน) ไว้ข้างคำถามแต่ละข้อ เพื่อช่วยให้ผู้สัมภาษณ์ที่ยังไม่ชำนาญให้คะแนนได้สม่ำเสมอใกล้เคียงกับผู้สัมภาษณ์ที่มีประสบการณ์มากกว่า

## เกณฑ์คุณภาพ

โปรดตรวจสอบทุกข้อก่อนส่ง Scorecard ให้ผู้ใช้นำไปใช้จริงในกระบวนการสัมภาษณ์:

- [ ] แต่ละ Competency มีนิยามที่ชัดเจน ไม่คลุมเครือ และตรงกับสิ่งที่ตำแหน่งนี้ต้องการจริง
- [ ] คำถามเป็นเชิงพฤติกรรม/สถานการณ์ ไม่ใช่คำถามปลายปิดที่ตอบใช่/ไม่ใช่
- [ ] สเกลคะแนนมีคำอธิบายระดับ (behaviorally anchored) ไม่ใช่ตัวเลขลอยๆ
- [ ] มีช่องบันทึกหลักฐานเชิงคุณภาพควบคู่กับคะแนนตัวเลขเสมอ
- [ ] จำนวน Competency เหมาะสม (4-6 ตัว) ไม่มากจนสัมภาษณ์ไม่ทันหรือประเมินเกินจริง
- [ ] มีหมายเหตุเตือนเรื่องกฎหมายแรงงาน/การเลือกปฏิบัติทุกครั้งที่ส่ง Output
- [ ] คำถามและเกณฑ์ทั้งหมดเกี่ยวข้องโดยตรงกับความสามารถในการทำงาน ไม่มีคำถามส่วนตัวที่ไม่จำเป็นแอบแฝงอยู่
