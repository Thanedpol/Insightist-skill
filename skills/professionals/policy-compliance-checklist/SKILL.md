# Policy Compliance Checklist

Skill นี้ช่วยสร้าง **checklist ตรวจสอบความสอดคล้อง (compliance checklist)** ระหว่างนโยบายหรือขั้นตอนการทำงานภายในองค์กร กับกฎระเบียบภายนอกที่เกี่ยวข้อง เช่น พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล (PDPA), กฎหมายแรงงาน, มาตรฐานความปลอดภัยข้อมูล, หรือกฎระเบียบเฉพาะอุตสาหกรรม (การเงิน, สุขภาพ, อาหาร ฯลฯ) เหมาะสำหรับทีม HR, Compliance, IT หรือเจ้าของธุรกิจที่ต้องการตรวจสอบตัวเองเบื้องต้นก่อนถูกตรวจสอบจากหน่วยงานภายนอกหรือก่อนปรึกษาที่ปรึกษากฎหมายอย่างเป็นทางการ

Skill นี้ทำหน้าที่เป็น **เครื่องมือคัดกรองเบื้องต้น (self-assessment tool)** เพื่อช่วยหาช่องว่าง (gap) ระหว่างสิ่งที่องค์กรทำอยู่กับสิ่งที่กฎระเบียบกำหนด — ไม่ใช่การตรวจสอบทางกฎหมายที่เป็นทางการ และไม่สามารถยืนยันได้ว่าองค์กร "ผ่าน" หรือ "ไม่ผ่าน" ตามกฎหมายจริง

## เมื่อไหร่ควรใช้ skill นี้

- กำลังร่างหรือปรับปรุงนโยบายภายใน (เช่น นโยบายความเป็นส่วนตัวข้อมูลพนักงาน/ลูกค้า, นโยบายการเก็บข้อมูล) และอยากรู้ว่าครอบคลุมประเด็นที่กฎหมายกำหนดหรือไม่
- ต้องเตรียมตัวก่อนถูก audit จากหน่วยงานกำกับดูแล หรือก่อนลูกค้า/พาร์ทเนอร์ขอดูเอกสาร compliance
- อยากตรวจสอบว่า SOP (Standard Operating Procedure) ของแผนกใดแผนกหนึ่งสอดคล้องกับกฎระเบียบที่เกี่ยวข้องหรือไม่ เช่น ขั้นตอนจัดการข้อมูลลูกค้าตาม PDPA
- ต้องรายงานผู้บริหารว่าองค์กรมีช่องว่าง (compliance gap) ตรงไหนบ้าง และควรจัดลำดับความสำคัญแก้ไขอย่างไร
- กำลังขยายธุรกิจเข้าสู่พื้นที่/อุตสาหกรรมใหม่ที่มีกฎระเบียบเฉพาะ และต้องการจุดเริ่มต้นในการตรวจสอบว่าต้องเตรียมอะไรบ้าง
- ทีมกฎหมาย/compliance ภายในต้องการ template checklist มาตรฐานไว้ใช้ซ้ำในการตรวจสอบรอบถัดๆ ไป

## ขั้นตอนการทำงาน

1. **ระบุขอบเขตการตรวจสอบ** — สอบถาม/สรุปจากผู้ใช้ว่า: นโยบาย/ขั้นตอนที่จะตรวจคืออะไร (เช่น นโยบายความเป็นส่วนตัว, ระเบียบการลาพนักงาน, ขั้นตอนจัดซื้อ), และกฎระเบียบที่เกี่ยวข้องคืออะไร (เช่น PDPA, กฎหมายแรงงาน, มาตรฐานอุตสาหกรรมเฉพาะ) ถ้าผู้ใช้ไม่ได้ระบุกฎระเบียบมา ให้ช่วยประเมินว่ากฎระเบียบใดน่าจะเกี่ยวข้องตามลักษณะธุรกิจ/นโยบายที่อธิบายมา และระบุไว้ว่าเป็นการสันนิษฐานเบื้องต้น
2. **อ่านเนื้อหานโยบาย/ขั้นตอนปัจจุบัน** — ถ้าผู้ใช้แนบเอกสารนโยบายมา ให้อ่านให้ครบก่อนเริ่มเทียบเคียง ถ้าผู้ใช้อธิบายด้วยคำพูด ให้สรุปความเข้าใจกลับไปก่อนดำเนินการต่อ
3. **แตกกฎระเบียบเป็นหัวข้อย่อยที่ตรวจสอบได้** — แปลงข้อกำหนดของกฎระเบียบที่เกี่ยวข้องให้เป็นรายการที่ตรวจสอบได้ทีละข้อ (เช่น PDPA → "มีการขอความยินยอมก่อนเก็บข้อมูลหรือไม่", "มีช่องทางให้เจ้าของข้อมูลขอลบ/แก้ไขข้อมูลหรือไม่")
4. **เทียบเคียงนโยบายปัจจุบันกับแต่ละหัวข้อ** — ระบุสถานะแต่ละข้อว่า "สอดคล้องแล้ว / สอดคล้องบางส่วน / ยังไม่สอดคล้อง / ไม่แน่ใจ-ต้องตรวจสอบเพิ่ม"
5. **จัดลำดับความสำคัญของช่องว่าง (gap)** — ให้คะแนนความเสี่ยงของแต่ละช่องว่างที่พบ (สูง/กลาง/ต่ำ) โดยพิจารณาจากผลกระทบหากไม่ปฏิบัติตาม (เช่น ค่าปรับ, ความเสียหายต่อชื่อเสียง, ความเสี่ยงทางกฎหมาย)
6. **เสนอแนวทางแก้ไขเบื้องต้น** — สำหรับแต่ละช่องว่างที่พบ ให้ข้อเสนอแนะสั้นๆ ว่าควรปรับปรุงนโยบาย/ขั้นตอนอย่างไร
7. **จัดทำ checklist ฉบับสมบูรณ์** — เรียบเรียงผลทั้งหมดตาม "โครงสร้าง Output" ด้านล่าง ให้เป็นรูปแบบที่นำไปใช้ตรวจซ้ำได้ในอนาคต (reusable checklist)
8. **ปิดท้ายด้วยคำแนะนำให้ผู้เชี่ยวชาญยืนยัน** และแนบ disclaimer เสมอ

## โครงสร้าง Output

```
# Compliance Checklist: [ชื่อนโยบาย/ขั้นตอนที่ตรวจสอบ]

ขอบเขตการตรวจสอบ: [อธิบายสั้นๆ]
กฎระเบียบที่ใช้อ้างอิง: [รายชื่อกฎระเบียบ] (หมายเหตุ: หากเป็นการสันนิษฐาน ให้ระบุไว้ตรงนี้)
วันที่ตรวจสอบ: [วันที่]

## สรุปภาพรวม
- จำนวนข้อที่สอดคล้องแล้ว: X / ทั้งหมด Y ข้อ
- จำนวนช่องว่างความเสี่ยงสูง: ...
- ระดับความพร้อมโดยรวม: [พร้อม / พร้อมบางส่วน / ยังไม่พร้อม]

## รายละเอียด Checklist

| ข้อ | หัวข้อตรวจสอบ | อ้างอิงกฎระเบียบ | สถานะ | ความเสี่ยงหากไม่แก้ไข | ข้อเสนอแนะ |
|---|---|---|---|---|---|
| 1 | ... | ... | [สอดคล้องแล้ว/บางส่วน/ยังไม่สอดคล้อง/ไม่แน่ใจ] | [สูง/กลาง/ต่ำ] | ... |
| 2 | ... | ... | ... | ... | ... |

## ช่องว่างที่ควรแก้ไขก่อน (เรียงตามความสำคัญ)
1. [ช่องว่างความเสี่ยงสูงสุด] — แนวทางแก้ไข: ...
2. ...

## ขั้นตอนถัดไปที่แนะนำ
- ...

> ⚠️ เนื้อหานี้เป็นข้อมูลทั่วไป ไม่ใช่คำแนะนำทางกฎหมาย ควรปรึกษาทนายความ/นักกฎหมายก่อนใช้งานจริงเสมอ
```

## ตัวอย่าง

**Input:** "บริษัทเราเก็บข้อมูลลูกค้า (ชื่อ เบอร์โทร อีเมล) ผ่านฟอร์มสมัครสมาชิกบนเว็บไซต์ อยากรู้ว่านโยบายความเป็นส่วนตัวที่มีอยู่สอดคล้องกับ PDPA หรือไม่"

**Output คร่าวๆ ที่ควรได้:**
- แตก PDPA เป็นหัวข้อตรวจสอบ เช่น "มีการแจ้งวัตถุประสงค์การเก็บข้อมูลชัดเจนหรือไม่", "มีช่องทางขอความยินยอม (consent) แยกจากเงื่อนไขการใช้บริการหรือไม่", "มีช่องทางให้ลูกค้าขอลบ/แก้ไขข้อมูลหรือไม่", "มีมาตรการรักษาความปลอดภัยข้อมูลหรือไม่"
- ระบุสถานะแต่ละข้อ เช่น "สอดคล้องบางส่วน" สำหรับการแจ้งวัตถุประสงค์ (มีแต่ไม่ครบ) และ "ยังไม่สอดคล้อง" สำหรับช่องทางขอลบข้อมูล
- จัดลำดับว่าช่องทางขอลบข้อมูลเป็นความเสี่ยงสูงสุดที่ควรแก้ก่อน พร้อมข้อเสนอแนะให้เพิ่มช่องทางติดต่อสำหรับคำขอใช้สิทธิของเจ้าของข้อมูล

## เกณฑ์คุณภาพ

- แตกกฎระเบียบเป็นหัวข้อที่ตรวจสอบได้จริง ไม่พูดกว้างๆ ว่า "ต้องทำตามกฎหมาย" โดยไม่ระบุว่าข้อไหน
- ระบุสถานะของทุกข้อชัดเจน (สอดคล้องแล้ว/บางส่วน/ยังไม่สอดคล้อง/ไม่แน่ใจ) ไม่ปล่อยว่างข้อใดข้อหนึ่ง
- จัดลำดับความสำคัญของช่องว่างตามความเสี่ยง ไม่ใช่เรียงตามลำดับที่พบเฉยๆ
- ถ้าไม่แน่ใจว่ากฎระเบียบข้อใดบังคับใช้กับกรณีของผู้ใช้จริงหรือไม่ ให้ระบุว่า "ควรยืนยันกับผู้เชี่ยวชาญ" แทนการฟันธง
- ทำ checklist ให้อยู่ในรูปแบบที่นำกลับมาใช้ตรวจซ้ำได้ในรอบถัดไป (reusable)
- แนบคำแนะนำขั้นตอนถัดไปและ disclaimer ทุกครั้งโดยไม่มีข้อยกเว้น

> ⚠️ เนื้อหานี้เป็นข้อมูลทั่วไป ไม่ใช่คำแนะนำทางกฎหมาย ควรปรึกษาทนายความ/นักกฎหมายก่อนใช้งานจริงเสมอ
